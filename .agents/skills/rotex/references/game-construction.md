# Game construction

Start with a play loop that can be tested by one player: action -> immediate feedback -> change in state -> new choice. State the fantasy and target audience, but treat examples from successful games as hypotheses rather than rules or guaranteed outcomes.

1. Inspect relevant experiences and identify observable mechanics: acquisition, risk, travel, waiting, social interaction, progression, and monetization. Do not reproduce protected art or copy a game wholesale.
2. Choose a specific player promise and one meaningful difference. Describe why the difference changes decisions or emotion, not just the theme or names.
3. Build a vertical slice with the interaction, camera/UI feedback, server authority, persistence boundary, and a reason to repeat. Keep reward rate and difficulty configurable.
4. Playtest for comprehension, time to first action, return motivation, failure states, and multiplayer behavior. Record observations; refine the loop before expanding the content or economy.
5. Add retention and monetization only after the loop is enjoyable. Avoid assuming a fixed percentage of borrowed mechanics predicts success.

Map each feature to the smallest reusable system that can own its mechanics. Keep the host game's fantasy, tuning, UI, and progression as integration policy; share systems across projects only after a second concrete use case exposes a stable contract.
